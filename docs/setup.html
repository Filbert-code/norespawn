NoRespawn — Setup Guide

Everything you need to take this repo from a fresh clone to a live, authenticated app — including every click you'll make in the Supabase, Google Cloud, and Vercel dashboards.

React + Vite TypeScript Tailwind v4 shadcn/ui Supabase (Postgres + Auth) Google OAuth Vercel hosting

1 Overview & architecture

How the pieces fit together.

  • Frontend — A React + Vite single-page app, deployed as static files on Vercel. This is all the user's browser downloads.
  • Backend — Supabase provides the Postgres database, authentication (including Google OAuth), and (optionally) Edge Functions. The browser talks to Supabase directly using the public anon key, secured by Row Level Security.
  • Identity — Google Cloud issues the OAuth client that lets users "Sign in with Google". Supabase brokers the OAuth handshake for you.
  • Keep-alive — A scheduled GitHub Action pings Supabase twice a week so the free-tier project never auto-pauses.
Cost: This entire stack runs on $0/month — Supabase free tier, Vercel Hobby, and GitHub Actions free minutes. The only free-tier gotcha (Supabase's 7-day pause) is handled by step 9.

2 Run the app locally

You're already in the cloned repo. Get it running before touching any dashboards.

  1. Make sure you have Node.js 20+ installed (node -v).
  2. Install dependencies:
npm install
  1. Create your local env file from the template:
cp .env.example .env.local
  1. Leave the values blank for now — you'll fill them in after creating the Supabase project (steps 3–4). Start the dev server: 
npm run dev

Open http://localhost:5173. You should see the NoRespawn landing page.

Tip: The landing page renders without Supabase configured. You only need env vars once you start using auth and the database.

3 Create the Supabase project

Dashboard: supabase.com/dashboard

  1. Click New project.
  2. Pick (or create) an organization on the Free plan.
  3. Set a Project name (e.g. norespawn), and a strong Database password — save this password in your password manager; you'll need it for direct Postgres access.
  4. Choose the Region closest to you (lower latency for a single user).
  5. Click Create new project and wait ~2 minutes for provisioning.

Grab your API credentials

  1. In the project, go to Project Settings (gear icon) → API.
  2. Copy these two values — you'll paste them in the next step:
Supabase fieldGoes into
Project URLVITE_SUPABASE_URL
Project API key → anon / publicVITE_SUPABASE_ANON_KEY
Never use the service_role key in the frontend or commit it anywhere. Only the anon key belongs in the browser — it's protected by Row Level Security.

Note your project ref too (the abcdefgh... subdomain in the Project URL). You'll need it for the Google redirect URI in step 5.

4 Wire up environment variables

Connect the local app to your new Supabase project.

Open .env.local and fill in the two values from step 3:

VITE_SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJ...your-anon-key...
Why the VITE_ prefix? Vite only exposes env vars that start with VITE_ to the browser bundle. The Supabase client reads these in src/lib/supabase.ts.

Restart npm run dev so the new env vars are picked up.

5 Configure Google OAuth

Console: console.cloud.google.com

5a. Create / select a project

  1. In the top bar, open the project picker → New Project (or reuse one).
  2. Name it (e.g. norespawn) and create it.

5b. Configure the OAuth consent screen

  1. Go to APIs & Services → OAuth consent screen (a.k.a. "Google Auth Platform" → Branding).
  2. Choose External user type and click Create.
  3. Fill in App name (NoRespawn), User support email, and a Developer contact email. Save and continue.
  4. On Scopes, you can leave defaults — Supabase requests email, profile, openid automatically. Save and continue.
  5. On Test users, add your own Google email address. While the app is in "Testing" mode, only listed test users can sign in — which is perfect for a single-user app.
You don't need to publish/verify the app for personal use. Leave it in Testing and just keep yourself on the test-users list.

5c. Create the OAuth client ID

  1. Go to APIs & Services → Credentials.
  2. Click Create Credentials → OAuth client ID.
  3. Application type: Web application. Name it (e.g. norespawn-web).
  4. Under Authorized JavaScript origins, add:
    • http://localhost:5173
    • https://YOUR-APP.vercel.app add after step 7
  5. Under Authorized redirect URIs, add your Supabase callback (this is the critical one): 
https://YOUR-PROJECT-REF.supabase.co/auth/v1/callback
  1. Click Create. Copy the Client ID and Client secret — you'll paste them into Supabase next.
Common mistake: The redirect URI points at Supabase (/auth/v1/callback), not at your Vercel app. Supabase handles the handshake and then redirects back to your app.

6 Enable Google in Supabase

Back in the Supabase dashboard.

  1. Go to Authentication → Sign In / Providers (or Providers).
  2. Find Google and toggle it on.
  3. Paste the Client ID and Client Secret from step 5c.
  4. Click Save.

Set redirect URLs

  1. Go to Authentication → URL Configuration.
  2. Set Site URL to your local dev URL for now: http://localhost:5173 (you'll switch this to your Vercel URL after deploying).
  3. Under Redirect URLs, add both:
    • http://localhost:5173/**
    • https://YOUR-APP.vercel.app/** add after step 7
  4. Save.
The /** wildcard lets Supabase redirect back to any path in your app after login (e.g. an /auth/callback route).

  3. Vercel auto-detects Vite. Confirm the build settings:

8 Post-deploy URL wiring

Now that you know your Vercel URL, fill in the placeholders from steps 5 & 6.

  1. Google Cloud → Credentials → your OAuth client:
    • Add https://YOUR-APP.vercel.app to Authorized JavaScript origins.
  2. Supabase → Authentication → URL Configuration:
    • Change Site URL to https://YOUR-APP.vercel.app.
    • Add https://YOUR-APP.vercel.app/** to Redirect URLs (keep the localhost one for local dev).
Custom domain later? Repeat this step with the custom domain in both Google and Supabase. Vercel handles the HTTPS certificate automatically.

9 Keep-alive GitHub Action

Free Supabase projects pause after 7 days of inactivity. The repo ships a workflow that pings it twice a week — you just need to add two secrets.

The workflow lives at .github/workflows/supabase-keepalive.yml. On GitHub, go to your repo → Settings → Secrets and variables → Actions → New repository secret and add:

Secret nameValue
SUPABASE_URLyour project URL (same as VITE_SUPABASE_URL)
SUPABASE_ANON_KEYyour anon key

To confirm it works, go to the repo's Actions tab → Supabase keep-alive → Run workflow. A green run that logs HTTP 200 means you're set.

It's scheduled for 09:00 UTC every Tuesday and Saturday — well within the 7-day window. Adjust the cron in the workflow file if you like.

10 Wire OAuth into the app later

The landing page's "Sign in" button isn't wired up yet. When you're ready, here's the minimal flow using the configured Supabase client.

Trigger Google login

import { supabase } from "@/lib/supabase"

async function signInWithGoogle() {
  const { error } = await supabase.auth.signInWithOAuth({
    provider: "google",
    options: {
      redirectTo: `${window.location.origin}/auth/callback`,
    },
  })
  if (error) console.error(error)
}

Read the session anywhere

const { data: { session } } = await supabase.auth.getSession()

// Or subscribe to changes:
supabase.auth.onAuthStateChange((_event, session) => {
  // update your app state with session?.user
})

Sign out

await supabase.auth.signOut()
Supabase handles the redirect dance, token exchange, and session refresh. The redirectTo must be one of the Redirect URLs you added in steps 6 & 8.
